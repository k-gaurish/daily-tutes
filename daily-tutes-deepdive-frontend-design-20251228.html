Overview & Tech Stack

This deep dive documents the complete frontend development workflow established while building the AI Travel Agent application. We'll explore everything from initial discovery through to deployment, including the tools, frameworks, and patterns that make modern AI application frontends possible.

What We Built

A complete frontend for an AI Travel Agent application featuring three core screens:

🏠
Landing Page

ASCII art animation cycling through TRAVEL/TRIP/VACATION with glare effects, shatter physics on click, and elegant icon carousel loader.

📝
Trip Form

Destination selection, date pickers, traveler count, interest tags, and budget selection with validation and state management.

🗓️
Itinerary Page

Day-by-day travel plan with Morning/Afternoon/Evening time slots, activity cards, and accommodation sections.

Section 02

Frontend Design SOP

A Standard Operating Procedure (SOP) is a documented workflow that ensures consistent, high-quality output every time. This Frontend Design SOP captures the complete process from idea to production.

When to Use This SOP

Not every project needs a frontend. Use this decision matrix:

✅ Needs Frontend
  • User-facing applications
  • Dashboards & analytics
  • Chat interfaces (like AI agents)
  • Visual output tools
  • Forms & data input
  • E-commerce flows
❌ Skip Frontend
  • CLI tools
  • API-only services
  • Data pipelines
  • Backend-only agents
  • Batch processing scripts
  • Internal automation

Section 03

Phase 1: Discovery

Discovery is about understanding what you're building and why. Skip this phase and you'll build the wrong thing beautifully.

Output: DISCOVERY.md

Every project should have a discovery document containing:

1. Jobs-To-Be-Done (JTBD) Statements

JTBD is a framework that focuses on what the user is trying to accomplish, not what features they want.

💡 JTBD Formula

When [situation], I want [motivation], so I can [outcome].

Markdown Travel Agent JTBD 
## Jobs-To-Be-Done

1. When I'm planning a trip but feel overwhelmed by options,
   I want an AI to create a personalized itinerary,
   so I can save time and discover hidden gems I'd miss.

2. When I'm traveling with family and have diverse interests,
   I want balanced daily plans that satisfy everyone,
   so I can avoid conflicts and maximize enjoyment.

3. When I have a fixed budget but want great experiences,
   I want optimized recommendations within my price range,
   so I can spend confidently without overspending.

2. Persona (1-2 Maximum)

Personas are fictional users that represent your target audience. Keep it to 1-2 to maintain focus.

👩‍💼
Maya Chen, 32 — Product Designer

Goals: Efficient trip planning, unique experiences, photo-worthy destinations
Frustrations: Generic travel guides, endless research, decision fatigue
Tech-savvy: Uses apps for everything, expects AI to "get" her
Quote: "I don't want the tourist version. I want to eat where locals eat."

Phase 2: Inspiration

Inspiration is about finding your visual direction. You're not designing in a vacuum — the best designs stand on the shoulders of great references.

Two Paths: Greenfield vs B2B

🌱 Path A: Greenfield (New Project)

Starting from scratch with no existing design system.

  1. Search similar apps on Mobbin or Dribbble
  2. Collect 5-10 reference screenshots
  3. Pick 1 "north star" design
  4. (Optional) Clone to Figma using html.to.design
  5. Extract and define design tokens
🏢 Path B: B2B (Existing System)

Adding to an existing product with established patterns.

  1. Screenshot existing system pages
  2. Clone pages to Figma using html.to.design
  3. Extract design tokens from DevTools
  4. Document existing components
  5. Identify gaps — what's new vs existing

💡 Pro Tip: Single Responsibility Iterations

Ask for one thing at a time. "Add glare animation" is better than "Add glare animation, word cycling, and fix the loader." Each iteration should be focused and testable.

Effective Prompting for v0

✅ Do

  • Reference design systems ("Aino-style")

❌ Don't

  • Ask for multiple major features at once
  • Expect pixel-perfect from vague descriptions
  • Forget to test in preview before exporting
  • Ignore accessibility

export interface TripRequest {

Backend API (FastAPI)

Python api.py 
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel
from travel_agent import agent

app = FastAPI()

# CORS configuration for local development
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],  # Frontend URL
    allow_methods=["*"],
    allow_headers=["*"],
)

class TripRequest(BaseModel):
    destination: str
    days: int
    travelers: int
    interests: list[str]
    budget: str

@app.post("/plan")
async def plan_trip(request: TripRequest):
    prompt = f"""
    Plan a {request.days} day trip to {request.destination}
    for {request.travelers} travelers.
    Interests: {', '.join(request.interests)}
    Budget: {request.budget}
    """
    result = agent.run(prompt)
    return {"itinerary": result}

Frontend API Service

TypeScript services/api.ts 
const API_BASE = 'http://localhost:8000';

export interface TripRequest {
  destination: string;
  days: number;
  travelers: number;
  interests: string[];
  budget: string;
}

export async function planTrip(data: TripRequest) {
  const response = await fetch(`${API_BASE}/plan`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data),
  });
  
  if (!response.ok) {
    throw new Error('Failed to plan trip');
  }
  
  return response.json();
}

Using the API in Components

TypeScript components/TripForm.tsx 
'use client';

import { useState } from 'react';
import { useRouter } from 'next/navigation';
import { planTrip } from '@/services/api';

export function TripForm() {
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const router = useRouter();

  const handleSubmit = async (formData: FormData) => {
    setLoading(true);
    setError(null);
    
    try {
      const result = await planTrip({
        destination: formData.get('destination') as string,
        days: Number(formData.get('days')),
        travelers: Number(formData.get('travelers')),
        interests: formData.getAll('interests') as string[],
        budget: formData.get('budget') as string,
      });
      
      // Store result and navigate
      sessionStorage.setItem('itinerary', JSON.stringify(result));
      router.push('/itinerary');
    } catch (err) {
      setError('Failed to plan trip. Please try again.');
    } finally {
      setLoading(false);
    }
  };

  // ... form JSX
}

Common Issues & Fixes

Hydration Errors

Next.js hydration errors happen when server-rendered HTML doesn't match client-rendered HTML.

❌ Problem: Using window in render
// This causes hydration error
const width = window.innerWidth;
return <div>{width}</div>;
✅ Solution: Use useEffect
const [width, setWidth] = useState(0);
useEffect(() => {
  setWidth(window.innerWidth);
}, []);

Layout Shifts (CLS)

Content that "jumps" as the page loads creates a jarring experience.

❌ Problem: Dynamic size without reservation
// Image loads and pushes content down
<img src="photo.jpg" />
✅ Solution: Reserve space with aspect-ratio
<img 
  src="photo.jpg"
  width=800
  height=600
  style={{ aspectRatio: '4/3' }}
/>
💡 The Polish Mindset

Polish isn't about perfection — it's about respect for your users. Every smooth animation, helpful error message, and edge case handled says "I thought about you when building this."

Understanding shadcn/ui

shadcn/ui is not a traditional component library — it's a collection of copy-paste components you own and customize.

📚 Analogy: Recipe vs Frozen Meal

Traditional component libraries (Material-UI, Chakra) are like frozen meals — convenient but hard to customize. You're stuck with their choices.

shadcn/ui is like a recipe with ingredients — you get the recipe (code) and you can modify anything: swap ingredients, adjust spices, make it your own.

Aspect Traditional Libraries shadcn/ui
Installation npm install package npx shadcn add button
Code Location node_modules (hidden) Your project (visible, editable)
Customization Limited to exposed props Full access to all code
Updates Auto-update via npm Manual update (you choose)
Bundle Size Includes unused components Only what you use

The cn() Utility Function

v0 generates use a helper function cn() for conditional class names:

TypeScript lib/utils.ts 
import { clsx, type ClassValue } from 'clsx';
import { twMerge } from 'tailwind-merge';

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}

// Usage example:
<button className={cn(
  'px-4 py-2 rounded',           // Base styles
  isActive && 'bg-orange-500',      // Conditional
  className                          // Override from props
)} />

Server vs Client Components

Next.js distinguishes between Server Components (default) and Client Components.

Aspect Server Components Client Components
Default Yes (no directive needed) No (requires 'use client')
Rendered On the server On the client (browser)
Bundle Not included in JS bundle Included in JS bundle
Use Cases Data fetching, static content Interactivity, useState, useEffect
Access Database, filesystem Browser APIs, window, document
TypeScript Client Component Example 
'use client';  // ← This makes it a Client Component

import { useState, useEffect } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);
  
  // Can use browser APIs in useEffect
  useEffect(() => {
    console.log('Mounted in browser');
  }, []);
  
  return (
    <button onClick={() => setCount(c => c + 1)}>
      Count: {count}
    </button>
  );
}
📚 Analogy: Restaurant Kitchen

Think of Server vs Client Components like a restaurant:

  • Server Components are the kitchen — heavy lifting, prep work, plating happens here (hidden from diners)
  • Client Components are the tableside — flambe, mixing cocktails, anything the customer interacts with directly

You don't bring the whole kitchen to the table. Same logic: don't send server code to the browser.

Symlinks Explained

A symlink (symbolic link) is like a shortcut that makes one folder appear to exist in another location.

Bash Creating a Symlink 
# Navigate to where you want the link
cd ~/g-ai-lab/projects/02-ai-travel-agent/working

# Create symlink: ln -s [source] [link-name]
ln -s ~/g-v0-lab/01-travel-agent-frontend frontend

# Verify with ls -la
ls -la
# Output: frontend -> /Users/you/g-v0-lab/01-travel-agent-frontend

# Now you can cd into frontend as if it's a real folder
cd frontend
npm run dev
📚 Analogy: Library Book Shortcut

Imagine you have a book on your desk, but you want it to appear on your bookshelf too without moving it. A symlink is like putting a card on the bookshelf that says "This book is actually on the desk." When someone looks for it on the shelf, the card redirects them to the desk.

Symlink Benefits

  • Edit anywhere: Changes in source reflect in the link (and vice versa)
  • Independent repos: Each repo has its own git history
  • Easy swapping: Point to different frontends by recreating the symlink
  • Clean structure: Backend project "sees" frontend without actually containing it

Managing Symlinks

Bash Symlink Management Commands 
# Remove a symlink (doesn't delete source!)
rm frontend

# Update symlink to point elsewhere
rm frontend
ln -s ~/g-v0-lab/02-new-frontend frontend

# Check if something is a symlink
file frontend
# Output: frontend: symbolic link to /path/to/source

# WARNING: rm -r on a symlink deletes the symlink AND follows into source!
# Always use just 'rm' for symlinks, never 'rm -r'

Word Cycling Logic

TypeScript Word Cycling Hook 
const WORDS = ['TRAVEL', 'TRIP', 'VACATION'];

function useWordCycle(intervalMs: number = 3000) {
  const [wordIndex, setWordIndex] = useState(0);
  const [isFlipping, setIsFlipping] = useState(false);

  useEffect(() => {
    const interval = setInterval(() => {
      setIsFlipping(true);
      
      setTimeout(() => {
        setWordIndex((prev) => (prev + 1) % WORDS.length);
        setIsFlipping(false);
      }, 300); // Half of flip animation
      
    }, intervalMs);

    return () => clearInterval(interval);
  }, [intervalMs]);

  return { word: WORDS[wordIndex], isFlipping };
}
💡 Performance Tip: Canvas Alternative

For very complex ASCII art with thousands of characters, consider using <canvas> instead of DOM elements. Each DOM element has overhead. Canvas renders as a single image, then you update pixels directly.

Learnings & Gotchas

Real-world development is full of surprises. Here are the key learnings from building the Travel Agent frontend.

v0.dev Learnings

📦
MCP Creates New Repos

Cannot push to existing repo subfolders. Use ZIP download + manual push for monorepo structures.

📂
ZIP Extraction

Files may extract directly without parent folder. Always check with `ls` before moving.

🔄
Iteration is Key

Multiple small prompts get better results than one massive prompt. Build up incrementally.

👁️
Preview Before Export

Test responsiveness and interactions in v0's preview. Catching issues early saves time.

Next.js Learnings

Hydration Errors

The most common Next.js pitfall. Happens when server HTML doesn't match client HTML.

Cause Fix
Using window or document in render Move to useEffect hook
Using Math.random() for keys/content Generate values in useEffect or use deterministic IDs
Date/time differences between server and client Format dates client-side in useEffect
Third-party libraries that access DOM on import Use dynamic imports with { ssr: false }

App Router Patterns

📊 Route File Mapping
app/page.tsx → / app/about/page.tsx → /about app/blog/page.tsx → /blog app/blog/[slug]/page.tsx → /blog/hello-world (dynamic) app/api/hello/route.ts → /api/hello (API route)

Git Learnings

Topic Lesson
Personal Access Token Required for HTTPS authentication. Password auth is deprecated. Generate in GitHub Settings → Developer settings → Personal access tokens.
Symlinks in Git Git tracks the symlink file, not the contents it points to. The linked content remains in its original repo.
Large Exports v0 exports include all shadcn components (80+ files). This is intentional — you own them.

CLI Learnings

❌ Common Mistakes
  • cd.. — Wrong! No space
  • # inside quotes — Not a comment!
  • mv file1 file2 dir/ — Moves both, not rename
  • rm -r symlink — Deletes through the link!
✅ Correct Syntax
  • cd .. — Space required
  • # comment — Outside quotes only
  • mv file1 file2 — One move at a time
  • rm symlink — Just rm, no -r
⚠️ Critical: Never rm -r a Symlink

Running rm -r symlink will follow the symlink and delete the original files! Always use rm symlink (no -r) to safely remove just the link.
