🔄 Part 15: Reranking

Basic vector search has a fundamental limitation: semantic similarity ≠ relevance. Just because documents are "similar" doesn't mean they actually answer the question. Reranking solves this by re-ordering results based on true relevance.

Two Approaches to Reranking

Approach How It Works Best For
RAG-Fusion + RRF Generate multiple query variations, retrieve for each, fuse rankings algorithmically Vocabulary diversity (users use different words than docs)
Cohere Re-Rank Use cross-encoder neural model to deeply score query-document relevance Precision-critical applications (legal, medical)

RAG-Fusion: Multi-Query Generation

  • Step 1: LLM generates 4-5 variations of the original query
  • Step 2: Retrieve documents for each query variation (parallel)
  • Step 3: Fuse results using Reciprocal Rank Fusion (RRF)
RRF(d) = Σ 1/(k + rank(d)) where k=60
📚 Analogy: Hiring Committee

Like having 5 interviewers evaluate candidates differently. A candidate who ranks highly across multiple interviewers (query variations) is more likely to be truly relevant than one who aced just one interview.

Cohere Re-Rank: Cross-Encoder Power

  • Bi-Encoder (Vector Search): Embeds query and document separately → fast but shallow
  • Cross-Encoder (Cohere): Processes query+document together → slow but deep understanding
Aspect Bi-Encoder Cross-Encoder
Speed ~1ms per query ~50-100ms per doc pair
Accuracy Good (85-90%) Excellent (95%+)
Understanding Query tokens can't see document tokens Full cross-attention between all tokens

⚡ Two-Stage Retrieval Architecture

Since cross-encoders are slow, you can't run them on your entire database. The solution is a two-stage architecture:

📊 Two-Stage Pipeline
User Query │ ▼ ┌────────────────────────────────────────┐ │ STAGE 1: BROAD RETRIEVAL (Vector) │ │ • Fast vector search │ │ • Cast wide net (20-100 candidates) │ │ • Goal: HIGH RECALL │ │ • Cost: FREE, Latency: ~50ms │ └────────────────────────────────────────┘ │ ▼ ┌────────────────────────────────────────┐ │ STAGE 2: PRECISION RERANKING (Cohere) │ │ • Cross-encoder scoring │ │ • Score each candidate deeply │ │ • Goal: HIGH PRECISION │ │ • Cost: ~$0.005, Latency: ~500ms │ └────────────────────────────────────────┘ │ ▼ Top 3-5 Most Relevant Documents
💡 Key Insight

Vector search is FAST but APPROXIMATE. Cohere is SLOW but PRECISE. Combine them: vector narrows the field, Cohere picks the winners. You get the best of both worlds.

🔍 Part 16: CRAG (Corrective RAG)

Reranking fixes wrong order, but what if documents are wrong, outdated, or missing? CRAG grades documents and finds alternatives when needed.

The CRAG Process

  1. Retrieve: Standard vector search retrieval
  2. Grade: LLM evaluates each document for relevance (yes/no)
  3. Decide: Based on grades, choose action:
    • All relevant → Generate directly
    • Some relevant → Keep good ones + web search
    • All irrelevant → Web search only
  4. Transform: Optimize query for web search if needed
  5. Generate: Answer using verified context
📊 CRAG Decision Flow
Grade All Documents │ ┌───────────┼───────────┐ │ │ │ ▼ ▼ ▼ ALL RELEVANT MIXED ALL IRRELEVANT │ │ │ ▼ ▼ ▼ Generate Keep good Web search directly + Web search only │ │ │ └───────────┴───────────┘ │ ▼ Generate Answer
📚 Analogy: Smart Research Assistant

A basic assistant hands you whatever they found. A CRAG-like assistant first evaluates what they found ("Is this relevant? Up to date?"), and if lacking, proactively searches elsewhere to fill the gaps.

🎯 When to Use What

Technique Use When Example Use Case
RAG-Fusion Vocabulary diversity problem E-commerce search, consumer apps
Cohere Re-Rank Precision is critical Legal contracts, medical queries
CRAG KB might be incomplete/stale Support bots, financial research
All Combined High stakes + varied terminology Healthcare clinical decision support
